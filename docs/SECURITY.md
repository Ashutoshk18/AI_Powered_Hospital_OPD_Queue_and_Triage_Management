# Security, Privacy & Threat Modeling Specification

## 1. Threat Modeling (STRIDE Analysis)

| Threat Category | Potential Risk in OPD System | Mitigation Implemented |
| :--- | :--- | :--- |
| **Spoofing** | Attacker impersonates doctor or administrator. | Cryptographic JWT signed with HMAC-SHA256 and verified on every protected route. |
| **Tampering** | Patient alters triage urgency or priority score in transit. | Server-side calculation only; triage tier and score inputs from client are ignored during check-in. |
| **Repudiation** | Clinical staff denies overriding a triage priority. | Immutable `AuditLog` and `TriageOverride` records capturing user ID, timestamp, old/new tiers, and justification text. |
| **Information Disclosure** | Patient accesses other patients' medical appointments or consultation notes. | Strict row-level authorization middleware filtering by authenticated `userId` and associated `patientId`. |
| **Denial of Service** | Flooding check-in or appointment booking endpoints. | Express rate limiting (`express-rate-limit`) on sensitive authentication and booking routes. |
| **Elevation of Privilege** | Receptionist calls doctor endpoints or grants admin rights. | Granular Role-Based Access Control (RBAC) enforced on the server before controller execution. |

## 3. Cryptographic & Credential Management
- **Password Storage:** Hashed using `bcrypt` with a work factor of 10 salt rounds. Plaintext passwords are never logged, returned in JSON, or persisted.
- **Session Tokens:** JSON Web Tokens (JWT) with configured expiration (default: 8 hours).
- **Environment Secrets:** Secrets (`JWT_SECRET`, `DATABASE_URL`) are read exclusively from system environment variables or `.env` files (excluded via `.gitignore`).
- **Initial Bootstrap:** The system checks on startup if an administrator account exists. If not, it provisions the initial administrator using environment variables (`INITIAL_ADMIN_EMAIL`, `INITIAL_ADMIN_PASSWORD`).

---

## 4. Input Validation & SQL Injection Defense
- **Zod Schema Validation:** All incoming request bodies, query strings, and path parameters pass through strict Zod validators. Extra unexpected keys are stripped or rejected.
- **Parameterized SQL via Prisma:** All queries use parameterized statements generated by Prisma ORM. No raw string interpolation is permitted.

---

## 5. Healthcare Data Privacy & Prototype Disclaimer
- All sample patients, doctor profiles, phone numbers, and vitals generated in this repository are **100% synthetic**.
- No real-world Protected Health Information (PHI) or Personally Identifiable Information (PII) is included or required.
- The prototype is designed for educational, research, and viva demonstration purposes. Production clinical deployment requires HIPAA/DISHA regulatory compliance assessments and institutional review board (IRB) approval.
